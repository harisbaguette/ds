# 디자인 시스템 구성요소 계층표

작성일: 2026-09-22. [디자인 시스템 정의](<디자인 시스템 정의.md>)의 아토믹 단위 원칙을 실제 구성요소 목록으로 펼친 표다. 디자인 시스템 한 벌을 만들 때 어떤 구성요소가 있어야 하고, 각 구성요소가 어느 층에 서는지를 한눈에 보기 위한 색인이며, 항목별 상세 명세와 사례는 [디자인 패턴 사전 항목 목록](<디자인 패턴 사전 항목 목록.md>)의 해당 ID를 따른다.

**결론: 디자인 시스템은 Token → Primitive → Atom → Molecule → Module → Pattern → Template → Page의 여덟 층으로 쪼개면 가장 관리하기 쉽다.** 아래층은 위층을 모르고, 위층은 바로 아래층만 조립해서 만든다. 층을 건너뛰어 끌어 쓰지 않는다.

## 층을 나누는 기준

| 층 | 뜻 | 쪼개는 판정 | 사전의 분류 |
|---|---|---|---|
| 0. Token | 모든 층이 공유하는 디자인 값. 그 자체로는 화면에 보이지 않는다 | 값 하나를 바꾸면 여러 부품이 함께 바뀌는가 | TOK |
| 1. Primitive | 토큰을 처음으로 눈에 보이게 만든 최소 표현 | 역할은 있으나 아직 상호작용이 없는가 | VIS, TYP, ICO, IMG |
| 2. Atom | 더 쪼개면 뜻이 사라지는 최소 UI 부품 | 혼자서도 쓰이고 상태를 가지는가 | ATM(원자), ACT, INP |
| 3. Molecule | 원자 몇 개를 묶어 한 가지 작은 일을 하는 부품 | 묶음을 풀어도 각 원자가 따로 쓸모가 있는가 | ATM(분자), INP, NAV |
| 4. Module / Organism | 분자와 원자를 모아 한 기능이나 한 구역을 완성한 단위 | 데이터와 동작을 연결해야 비로소 뜻이 생기는가 | ATM(유기체), MOD, DAT |
| 5. Pattern | 여러 부품이 함께 움직이는 규칙. 특정 부품이 아니라 사용 방법 | 같은 문제를 다른 부품 조합으로도 풀 수 있는가 | FLW, STA, SRH 등 |
| 6. Template | 실제 내용 없이 자리와 크기만 잡은 화면 골격 | 내용을 바꿔도 구조가 그대로 남는가 | LAY, ATM(템플릿) |
| 7. Page | 진짜 내용과 데이터를 넣은 완성 화면 | 실제 글과 사진으로 길이·빈칸·최악 경우를 시험했는가 | ATM(페이지), FLW |

## 실무에서 특히 분리해 둘 다섯 영역

Token, Icon, Component(Atom·Molecule), Module, Pattern 다섯 영역은 서로 다른 속도로 바뀌고 다른 사람이 관리하므로 저장 위치와 문서를 분리한다.

| 영역 | 바뀌는 속도 | 분리하는 이유 |
|---|---|---|
| Token | 가장 느림 | 값 하나가 전체에 퍼지므로 변경 승인 절차가 필요하다 |
| Icon | 느림 | 세트 단위로 교체되며 그리드·선 굵기 규칙이 따로 있다 |
| Component | 보통 | 코드와 함께 배포되며 API·상태·접근성 시험을 가진다 |
| Module | 빠름 | 제품 기능에 따라 늘어나고 데이터 연결이 필요하다 |
| Pattern | 제품마다 다름 | 부품이 아니라 사용 규칙이므로 코드가 아닌 문서와 예시로 관리한다 |

Card 같은 것은 컴포넌트이고, 검색 → 필터 → 결과처럼 여러 컴포넌트가 함께 동작하는 규칙은 Pattern으로 따로 관리한다. 같은 Pattern을 여러 스타일의 부품으로 구현할 수 있어야 하며, 이것이 [디자인 시스템 정의](<디자인 시스템 정의.md>)에서 말하는 스타일별 디자인 시스템의 전제다.
