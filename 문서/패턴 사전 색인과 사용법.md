# 패턴 사전 색인과 사용법

작성일: 2026-09-21. [디자인 시스템 정의](<디자인 시스템 정의.md>)를 실제 사전으로 만들기 위한 색인이자 사용법이다. 분류별 수록 항목은 [사전/](<사전/>) 폴더에 있고, 이 문서는 그것을 읽는 기준·조사 기준·분류 색인·항목에 붙일 정보 규격·선택과 재사용 규칙·완료 기준을 담는다. 레퍼런스의 항목과 분류를 대조하고, 웹앱·모바일 앱·웹사이트·블로그·기능 사이트·어필리에이트·HTML 문서에 필요한 항목을 정리했다.

**목표는 필요한 패턴을 빠뜨리지 않고, AI가 스타일 선택부터 조합·구현·마무리까지 맡는 100% 완성이다.** 대표 항목만 남기는 요약 사전이나 항목 수에 상한을 둔 목록을 목표로 하지 않는다. 현재 파일은 그 목표를 위한 수록·조사 대장이며, 각 항목의 상세 명세·코드·시각 검증은 별도의 진행 상태로 관리한다.

**65개 분류, 3625개 수록 항목**으로 확장했다. 기준 866개, 부품 1033개, 구성 991개, 모듈 633개, 흐름 102개다. 근거는 원문 개념 확인 655개, 프로젝트 요구에 따른 확장 2970개로 구분한다. 확장 2970개 가운데 2619개는 AI 모델 지식에서 꺼낸 [MK] 항목이다. 이는 서로 다른 층위의 사전 레코드 수이며, 독립적인 부품 수나 완성률이 아니다.

## 목록을 읽는 기준

- **기준:** 여러 부품과 화면이 공유하는 표현·동작 원칙. 독립적인 UI 패턴 수와 구분한다.
- **부품:** 따로 사용하거나 교체하는 UI 단위.
- **구성:** 반복되는 배치·상호작용 문제를 해결하는 패턴.
- **모듈:** 부품과 구성을 결합한 기능·콘텐츠 영역.
- **흐름:** 여러 상태나 화면을 거쳐 사용자의 일을 끝내는 과정.
- **확인:** 참고 자료의 본문·공개 색인·예제 설명에서 해당 개념을 확인했다. 자료마다 실제 열람 범위는 출처 표에 적었다. 모든 상세 페이지나 작동 예시를 검증했다는 뜻은 아니다. 한국어 이름과 용도는 이 프로젝트에 맞게 정리했다.
- **확장:** 참고 자료와 기존 정의를 바탕으로 제안한 항목. 원문에 같은 이름의 구현이 있다는 뜻은 아니다.
- **확장 [MK]:** AI 모델 지식에서 꺼낸 항목. 이름·역할·종류는 이 프로젝트 기준으로 정리했다. 49번 분류의 금지 항목과 50번 분류의 시험 조건은 채택 목록이 아니라 검출 기준으로 읽는다. 54~64번은 패턴이 아니라 아이콘·계층·토큰·상태·입력·소리·문구·표기·접근성 역할·자산의 이름 사전이며, 패턴 항목이 이 이름을 가져다 쓴다.

상위 항목과 하위 항목을 함께 수록한다. 예를 들어 DAT-17은 차트 선택의 입구, CHR는 개별 표현 선택지다. 둘을 서로 독립적인 완성 부품으로 합산하지 않는다. 중복 통합 뒤 ID에 빈 번호가 남을 수 있으며, 기존 200개 항목의 ID는 보존한다.

같은 역할의 동의어는 한 항목으로 묶는다. 토큰·크기·색상·상태만 다른 것은 변형으로 관리하고, 역할이나 조합 조건이 달라지는 경우에 항목을 나눈다. 예를 들어 `Select`와 `Dropdown Menu`는 값 입력과 행동 선택이 달라 구분하며, `Toast`와 `Snackbar`는 하나로 묶는다.

**취향과 좋은·나쁜 디자인의 판단 기준은 [디자인 시스템 정의](<디자인 시스템 정의.md>)가 정한다. 사전은 그 기준을 수록과 선택에 이렇게 적용한다.** 수록 범위는 취향으로 좁히지 않고 모든 출처를 받아들이되, 각 항목의 시각 사례와 스타일별 구현을 고를 때 정의 문서의 취향을 적용한다. 국내·미국 라이브러리의 기능 분류를 참고해도 그 기본 외형을 기본 스타일로 채택하지 않고, 일본 디자인의 표현을 하나로 고정하지도 않는다. 일본 디지털청 자료는 기본 설계와 사용성의 참고 자료로 쓴다.

사전에 수록됐다는 이유만으로 화면에 넣지 않는다. 튜토리얼·도움말·온보딩 항목을 포함하더라도, 기본 화면의 혼란을 설명으로 메우는 용도로 자동 선택하지 않는다. 교육 콘텐츠 자체와 인터페이스 사용법의 학습 부담을 구분한다. 명확한 행동 라벨·필수 수치·본문·보조기술 안내는 역할에 맞게 유지하고, 의미를 추측해야 하는 아이콘은 노 텍스트의 성공 사례로 보지 않는다.

## 범위를 줄이지 않기 위한 조사 기준

이전 200개 목록은 일반 웹 UI에 치우쳤다. 차트·편집기·모바일을 큰 이름 하나로 묶었고, 업종별 과제와 시각 표현도 부족했다. 이번 판에서는 큰 범주를 하위 선택 문제로 풀고, 다음 축을 서로 교차해 누락을 찾는다.

| 조사 축 | 빠뜨리지 않고 볼 대상 | 이 사전에서 연결할 정보 |
|---|---|---|
| 사용자 과제 | 탐색·선택·입력·생성·편집·비교·거래·학습·소통·운영·복구 | 부품·모듈·사용자 흐름 |
| 시각 표현 | 조판·비율·정렬·여백·사진·그림·색면·재질·움직임 | VIS, ART, TYP, IMG, ANM, FX |
| 구성 규모 | 토큰·작은 부품·복합 영역·화면 골격·여러 화면의 흐름 | 부모·자식·조합 관계 |
| 매체 | 웹사이트·웹앱·모바일 웹·네이티브 앱·블로그·기능 사이트·어필리에이트·HTML 문서·인쇄 | 매체별 구현·대체 표현 |
| 사용 환경 | 터치·마우스·키보드·보조기술·가변 화면·언어·연결 상태 | 상태·입력·접근성 조건 |

분야 이름만 바꿔 항목을 늘리지 않는다. 예를 들어 은행 로그인과 쇼핑몰 로그인은 같은 기본 패턴을 공유한다. 좌석 선택, 연결선 편집, 주소 탐색처럼 실제 판단·데이터·조작이 달라질 때 별도 항목으로 나눈다.

조사 출처에는 패턴 사전, 디자인 시스템, 코드 라이브러리, 실사용 화면·흐름 아카이브, 시각 디자인 갤러리, 전문 도구, 플랫폼 문서, 연구·표준 문서를 모두 포함한다. 어느 한 종류의 목록을 세계 전체 목록으로 취급하지 않는다.

## 적용 과제로 조합 검증하기

전체 사전의 수록 범위는 유지하면서, 실제 과제마다 필요한 항목을 연결해 검증한다. 아래 묶음은 구현·검증 순서의 예시이며, 최종 수록 범위를 이 대상으로 제한하지 않는다. 공통 기준과 해당 화면의 상태 처리를 함께 준비한다.

| 적용 대상 | 연결할 항목 예 | 확인할 과제 |
|---|---|---|
| 블로그·콘텐츠 사이트 | LAY-01, NAV-01·09·13, EDT-01·02·04·06, FLW-01 | 목록에서 글을 찾아 긴 한글 본문을 읽고 다른 글로 이동 |
| 브랜드·소개 웹사이트 | NAV-01·13, WEB-01~04 중 하나, WEB-05·11·13 | 핵심 내용을 이해하고 문의 또는 다음 행동까지 진행 |
| 기능 사이트 | INP-01·02·12, STA-04·07·08·12, FLW-03 | 자료를 넣어 결과를 받고 잘못된 입력에서 복구 |

## 각 항목에 붙일 정보

항목 하나를 보면 **무엇을 해결하는지, 언제 쓰는지, 어떻게 구현하는지, 어디까지 바꿔도 되는지** 알 수 있어야 한다. 그러기 위해 각 항목에 아래 정보를 붙인다. 별도 패턴으로 개수를 늘리지 않고 해당 항목에 붙이며, 현재 사전에는 항목명·종류·역할·근거만 채워져 있고 아래 내용은 상세화 단계에서 채운다. 모든 항목에 같은 칸을 억지로 채우지는 않는다. 그 항목을 고르고 재현하는 데 필요한 정보를 갖춘다.

| 이름과 식별자 | 사람과 AI가 같은 항목을 정확히 가리킬 이름, 한국어·영어 명칭과 흔히 쓰는 동의어, 항목 ID |

스타일 이름 자체, 밝은·어두운 색상 변형, 효과의 매개변수, 개별 브랜드 사례를 새 UI 패턴으로 중복 등록하지 않는다. 별도 스타일 기록과 변형·사례로 연결한다. 항목 수의 상한은 두지 않는다. [레퍼런스 출처 대장](<레퍼런스 출처 대장.md>)과 미해결 항목을 유지하면서, 새로운 출처·사용자 과제에서 누락이 발견되면 사전에 편입한다. 현재의 수록 수를 세계 전체 패턴 수나 완성률로 해석하지 않는다.

## 같은 스타일 안에서 조합하기 위한 항목 정보

스타일은 색상 프리셋으로 축소하지 않는다. 각 항목의 기능 정의는 공유하되, 아래 정보를 스타일마다 갖춘다. 예를 들어 같은 기사 목록도 글자의 위계·이미지 비율·정렬·밀도·구분 방식이 달라야 다른 편집 방향을 표현할 수 있다.

| 기록 | 반드시 연결할 내용 |
|---|---|
| 스타일 정체성 | 실제 사례, 만들 인상, 피할 인상, 어떤 사용자·콘텐츠에 맞는지 |
| 표현 값 | 의미별 색상·글꼴·크기·행간·간격·선·모서리·깊이·움직임 |
| 구성 규칙 | 먼저 보이는 핵심 의도와 행동, 시선의 순서, 강조 비율, 정보 밀도, 반복·변화·빈 공간의 관계 |
| 자산 규칙 | 사진·일러스트·아이콘·질감의 시점·비율·선·명암·크롭 |
| 부품 구현 | 스타일 ID·패턴 ID·지원 플랫폼·버전·실제 미리보기 |
| 조합 조건 | 넣을 수 있는 영역, 부모·자식 관계, 최소 너비, 간격 책임, 데이터·이벤트 연결 |
| 허용 변형 | 어떤 크기·밀도·강조·배치를 바꿀 수 있는지 |
| 조합 금지·대안 | 기능 중복, 위계 충돌, 서로 맞지 않는 밀도·모션·표현과 대체안 |
| 사용자 취향 | 일본 쪽 표현·시각 중심·적은 텍스트·즉각적인 이해를 명시된 선호로 연결. 추가 사례와 AI의 잠정 해석은 구분 |
| 검증 증거 | 실제 한글 콘텐츠·화면 크기·상태·흐름의 렌더와 사용 결과 |

일본 레퍼런스를 우선하되 ‘일본은 미니멀’처럼 고정하지 않는다. 사진 중심 브랜드, 그림으로 과정을 보여 주는 화면, 시각화로 복잡한 관계를 정리한 화면 등에서 의미를 바로 전달하는 방식을 살핀다. 다른 표현도 사전의 수록 범위에 포함하되, 내 작업에 적용할 때는 명시된 취향과 좋은·나쁜 디자인 기준을 따른다. 한국·미국 기반의 기능 라이브러리를 쓰더라도 그 기본 외형이 자동으로 결과물의 스타일이 되지 않게 한다.

새 라이브러리에서 비슷한 버튼 100개를 발견하면 버튼 100종을 수록하는 대신, 기존 버튼 항목에 구조·표현·상태의 변형으로 연결한다. 화면 전체의 표현 체계가 달라지는 경우에만 다른 스타일로 묶는다.

| 추이·분포·비중·관계 중 무엇을 읽어야 하는가? | DAT-17에서 CHR의 선택지로 연결 |
| 이 업종만의 과제인가, 일반 과제의 문구 변형인가? | DOM의 고유 과제만 추가하고 공통 로그인·폼·목록은 재사용 |
| 이 효과가 내용·선택·조작에 기여하는가? | ANM·FX의 목적을 확인하고 불필요하면 사용하지 않음 |
| 설명을 읽거나 튜토리얼을 거쳐야 핵심을 이해하는가? | 내용·구조·시각 표현·조작을 먼저 재설계. ART·IMG·CHR 등의 시각 표현을 검토하되 의미 없는 이미지와 모호한 아이콘은 제외 |
| 부품 하나가 좋은가, 실제 조합도 좋은가? | 같은 스타일의 실제 콘텐츠·전체 화면·흐름으로 검증 |

## 조사·수록·구현을 구분하는 완료 기준

**출처를 열었다고 사전이 완성된 것은 아니다.** 다음 상태를 항목과 출처에 각각 기록한다. 이번 파일은 수록 항목과 근거를 확장한 결과이며, 실제 코드·스타일별 화면·조합 검증을 완료했다고 표시하지 않는다.

| 단계 | 완료로 볼 수 있는 증거 | 현재 문서의 역할 |
|---|---|---|
| 발견 | 출처·분류·원본 위치가 기록됨 | [레퍼런스 출처 대장](<레퍼런스 출처 대장.md>)으로 추적 |
| 본문 확인 | 실제 설명·예시의 해당 부분을 확인 | 출처 표에서 열람 범위 구분 |
| 명세 작성 | 사용 조건·대안·구조·상태·콘텐츠·조합 규칙이 채워짐 | 공통 양식과 수록 역할을 정의 |
| 스타일 구현 | 같은 스타일의 토큰·자산·코드·미리보기가 연결됨 | 구현 완료 판정은 하지 않음 |
| 조합 검증 | 실제 콘텐츠·플랫폼·입력·상태·흐름의 증거가 있음 | 검증 대상과 연결 기준을 정의 |
| 자율 완성 | 사람이 디자인을 고르거나 결함을 고치지 않아도 결과 사용 가능 | 최종 성과로 측정할 목표 |

전체 완료율은 아직 산정하지 않는다. 분야를 임의로 빼거나 미접근 자료를 조사 완료로 바꿔 100%를 만들지 않는다. 산정할 때는 명세 완성률, 스타일별 구현률, 실제 조합 검증률, 사람의 디자인 보정 없는 과제 완료율을 따로 기록한다.

### 남아 있는 조사·정리 작업

- [레퍼런스 출처 대장](<레퍼런스 출처 대장.md>)의 "추가 조사에서 항목에 연결한 출처"에 이름만 적힌 기호 36개의 원문 주소를 확인해 기호표에 등록한다.

| 남은 일 | 해결해야 할 내용 | 완료 증거 |
|---|---|---|
| 접근 실패·경로 변경 복구 | [레퍼런스 출처 대장](<레퍼런스 출처 대장.md>)의 실패·셸·로그인·용도 변경 출처 재확인 | 현재 공식 문서·저장소·공개 자료의 확인 위치 |
| 장기 사용 흐름 | 실사용 앱의 가입·업무·복구·종료 전체 경로 관찰 | 진입부터 완료까지 이어지는 상태·화면 기록 |
| 실제 일본 디자인 사례 | 분류명뿐 아니라 원본의 조판·비율·이미지·동작 관찰 | 시각 증거와 적용 원리·개인 취향의 구분 |
| 업종별 전문 과제 | DOM·확장 항목의 실제 업무·용어·예외 확인 | 해당 서비스 원문 사례와 수정된 명세 |
| 스타일별 조합 범위 | 각 패턴·매체·밀도·콘텐츠 조건의 지원 상태 연결 | 지원·미지원·검증 전이 구별된 조합표 |
| 신규 표현과 새로운 출처 | 새 매체·기술·기법에서 기존 체계의 빈틈 발견 | 신규 편입 또는 기존 변형으로 통합한 기록 |

이 표의 미해결 항목은 최종 수록 범위에서 제외한 항목이 아니다. 조사와 구현이 끝날 때까지 남겨 두는 작업이다. 책·논문, 유료·로그인 자료, 비공개 시스템까지 모두 읽었다고 주장하지 않는다. 이미 조사한 출처에서도 더 깊은 페이지와 새로운 항목이 계속 추가될 수 있다.
