# 패토브 뼈대 시각 검수

> 이전 작업 이력. 사용자가 내부 예시 중심의 작업 범위를 정정했다.
> 최신 범위와 결과는 [사이트 외부 검수](패토브-사이트-외부-검수.md)를 따른다.

2026-09-24. 사용자의 “시안 이미지보다 너프됨”과 후속 “사이트 전체·패턴·컴포넌트도 취향 이미지 수준이 아니다” 지적에 따라 루트 실행 화면을 재작업했다.
상세 본문과 전체 사전 데이터는 작성하지 않았다. 이 기록은 자체 검수이며 사용자 승인을 뜻하지 않는다.

## 반려와 수정

| 검수 | 직접 확인한 반려 사유 | 수정 |
|---|---|---|
| 기존 구현 | Arial 워드마크, 대체 글꼴, 회색 막대 중심의 작은 예시, 고양이·풍경 그림 누락 | 로컬 Pretendard·Outfit 포함, 예시의 실제 UI 형태와 원본 SVG 복원 |
| 1차 렌더 | 스타일의 보조 글자·체크박스가 작음. 수평선이 제목을 가름. 모바일 오류 안내가 사라짐 | 스타일 카드 724px, 본문·체크박스 확대, 풍경 구도 조정, 오류 안내 유지 |
| 2차 렌더 | 목록 썸네일 내부가 잘림. 폼의 가로 그림이 눌리고 글자가 작음 | 크기별 정보량 조정, 목록 썸네일 확대, 가로 풍경 분리, 입력 글자 확대 |
| 3차 렌더 | 폼 그림의 CSS Grid 최소 크기 때문에 이미지가 이름 라벨을 덮음 | 그림 컨테이너를 block으로 교체하고 겹침 회귀 검사 추가 |

## 후속 반려를 반영한 전체 재작업

앞의 세 차례는 누락·잘림을 줄인 검수였다. 이를 미감의 완성이나 사용자 승인으로 판단한 것이 잘못이었다.
지정된 6개 스킬과 해당 역할 문서, 취향 장부, 프로젝트 정의, 원본 취향 이미지를 읽고 다음을 수정했다.

| 검수 관점 | 화면에서 확인한 문제 | 반영 |
|---|---|---|
| Human | “보면 고를 수 있는 도구”여야 하는데 작은 예시와 반복된 회색 면으로 취향 판단이 어려움 | 큰 예시·짧은 이름·직접 저장. 상세 본문은 확정 후 작성한다는 범위 유지 |
| Visual | 바깥 화면의 제목·분류·검색 위계가 약하고, 모든 예시가 같은 작은 부품처럼 보임 | 호스트 전체 재조정. 패턴별 무대색·구도, 큰 진행 숫자, 목록형 탭, 알림 겹침, 새 선화 |
| Asset | 초기 생성 고양이가 사실적이고 잔선이 많아 원본 취향의 절제와 다름 | 첫 결과 반려 → 간결한 선화 재생성 → 투명 배경 편집. 최종 앱 렌더 대조 |
| UX | 저장을 위해 상세로 들어가야 함. 스타일 이름이 예시 아래에 있어 첫 화면에서 보이지 않음 | 카드 직접 저장, `/` 검색, 스타일 이름·패턴 보기 동작을 카드 위로 이동 |
| UI | 약한 저장 아이콘, 선화 진행률의 어두운 트랙, 스타일 간 부품 줄 높이 차이 | 저장 아이콘 대비·이름과 정렬 수정, 트랙 조정, 컴포넌트 줄 높이 통일, 색상 토큰 공유 |
| Quality | 풍경 스타일 오류 안내 대비 3.71:1, 보조 날짜·개수 4.21:1 | 오류·보조 텍스트 색 재조정. 재측정 최소 4.68:1 |

추가로 파일 실행에서 CSS mask가 아이콘을 표시하지 못하는 중간 수정본을 반려했다.
원본 SVG를 인라인 묶음으로 바꾸어 파일 실행과 HTTP 실행에서 모두 표시하고, 글자와 같은 색 토큰을 따르게 했다.
프로그래밍으로 초점을 옮긴 본문·대화상자 제목의 불필요한 큰 테두리는 제거하고 실제 조작의 키보드 초점은 유지했다.

최종 눈검사 범위: 패턴 12종×4스타일, 기본 목록, 스타일의 4장면×3스타일,
상세·비교·저장 있음·저장 없음·검색 결과 없음. 데스크톱과 모바일의 실제 캡처를 확인했다.
모바일 스타일은 축소된 3열 대신 한 열로 읽는다. 비교용 데스크톱 컴포넌트 화면은 같은 줄에서 형태가 대응한다.

## 확인 기준

- 375px·1440px 실제 렌더를 시안과 대조한다. 그림 존재 여부만으로 통과시키지 않는다.
- 선화·컬러블록·풍경은 글꼴·구도·그림·버튼 형태로 구별되어야 한다.
- 탐색·목록·스타일 집중/입력/피드백에서 글자와 핵심 요소가 잘리지 않아야 한다.
- 320·375·768·1101·1440·1920px에서 글꼴·이미지·아이콘 로드, 가로 넘침, 미리보기 잘림, 그림과 폼 겹침을 검사한다.
- 상세 본문 미작성과 실제 동작이 없는 시각 예시는 뼈대 범위에 맞춘 의도적 제한이다.

## 검증 자료

- `npm test`: 검색·분류·상세·비교·저장·뒤로 가기·초점·저장소 오류·직접 저장·컴포넌트 화면 등 61개 통과.
- `npm run test:visual`: 54개 화면 조합에서 글꼴·이미지·아이콘·영역 잘림·폼 가림 검사 통과.
- `npm run test:design`: 375·1440px의 26개 주소/화면 조합에서 조작 영역·이름·텍스트 대비·페이지 넘침 검사. 발견 0.
  실제 조작 최소 44px, 측정한 텍스트 대비 최소 4.68:1. 텍스트 노드 1,294개·조작 요소 568개를 측정했다(화면 간 중복 포함).
  이 검사는 WCAG 전체 인증이나 실제 스크린리더 사용자 실험이 아니다. 접근성 트리 읽기 순서는 별도로 확인했다.
- `test-results/01-desktop.png`, `05-styles.png`, `06-mobile.png`: 최종 주요 화면.
- `test-results/09-components.png`, `test-results/visual/`: 스타일별 패턴, 목록, 집중·입력·피드백·컴포넌트의 실제 캡처.
- `test-results/before/`, `test-results/round-1/`: 수정 전과 중간 단계 캡처.
- `design_lint.py`: ERROR 0, WARN 74. 비조작 썸네일·보조 라벨의 작은 글자와 의도한 반경,
  HTML theme-color가 경고 대상이다. 실제 본문과 구별해 검토했다. CSS 직접 색 값은 토큰으로 옮겼다.

## 성능 기록과 판정의 한계

`test-results/design-audit.json`의 로컬 Chrome 진단: 이번 검수 실행들에서 LCP 40~52ms, CLS 0.000275,
관찰된 입력 이벤트 최대 32ms, 초기 자원 본문 합계 약 3.02MB.
인터넷·모바일 실기기 측정이 아니며, 이 짧은 실행으로 실제 INP나 배포 환경 Core Web Vitals를 판정하지 않는다.
전체 한글 폰트와 원본 선화가 포함되어 초기 200KB 압축 목표는 충족하지 않는다.

이번 결과는 시각 방향을 검토할 수 있는 뼈대다. 상세 본문·실동작 컴포넌트 라이브러리 완성과는 구별한다.
테스트 통과나 자체 평가로 “프로 디자이너급 승인”을 부여하지 않는다. 수정본에 대한 사용자 평결은 아직 없다.
