# 파토브 구현 구조

2026-09-26. 목표의 정본은 [디자인 시스템 정의](<문서/디자인 시스템 정의.md>)다. 이 문서는 현재 코드의 구조를 설명하며 완료 기준을 대체하지 않는다.

사용자 실행 진입점은 상위 폴더의 `패토브 실행.exe` 하나다. 이 문서를 포함한 개발·운영 파일은 `실행관리(Ops-Run)`에 모았다. 실행기는 자신의 위치를 기준으로 서버를 찾고, 같은 폴더의 서버가 준비됐는지 확인한 후 브라우저를 연다. 웹 주소와 문서·자산의 내부 상대 경로는 그대로다.

## 화면

주 메뉴는 **스타일·사전**이다. 첫 화면에서 메인 스타일의 부품 크기·상태·조합을 시트로 비교한다. 별도 거대 표지를 거치지 않는다. 사전은 실제 시각 예시와 행동·입력·선택·이동·찾고 고르기의 목적에서 시작한다. 전체 원문도 검색하고 분류별로 열 수 있다. 사전의 첫 탭은 **토큰**이다. TOK 146항목과 계층표의 토큰 층 30묶음을 모으고, 항목 이름의 ` — ` 앞말(색·글자·간격·움직임 등)을 종류 필터로 쓴다. 한 번만 나오는 앞말은 기타로 묶는다.

상세는 실제 부품, 쓰는 조건, 연결된 하위 부품, HTML·React 소스와 설치 방법을 한곳에 모은다. 정의만 있는 항목은 구현 전으로 표시한다. 계층표와 원문은 보조 자료로 연결하며 별도 주 메뉴를 만들지 않는다. 기존 주소와 저장한 패턴은 유지한다.

사이트 외곽과 실제 부품·조합에 같은 메인 스타일 토큰을 적용한다. 비교 시트와 긴 문서는 평평하게 두고, 조작 부품에 양각·음각을 사용한다. 부품 비교용 고정 hover·pressed·focus 표본과 실제 조작은 구분한다. 카드 미니어처는 탐색 링크이고, 상세의 실물에서 조작한다.

## 원본과 생성물

| 원본 | 책임 |
|---|---|
| `src/system/registry.js` | ID, 역할, 목적, 사전 연결, 의존성, 호환 조건, 버전과 Trial 상태 |
| `src/tokens/primitive/<종류>.css` | 원시 값. 종류마다 한 파일씩 스무 파일(`color`부터 `breakpoint`까지, 순서는 `scripts/tokens.mjs`의 `kinds`). hex와 px·ms 같은 값이 적힌 유일한 곳 |
| `src/tokens/semantic/<종류>.css` | 역할 이름 `--p-*`. 같은 종류의 원시 값만 참조하며, 스타일을 바꿀 때는 이 층의 참조만 교체 |
| `scripts/tokens.mjs` | 두 층 폴더를 읽어 층 규칙을 검사하고, 부품 CSS가 읽는 역할의 종류와 배포용 원시 값을 계산 |
| `src/styles/themes.css` | 메인 스타일 표본 규칙. 토큰은 선언하지 않음 |
| `src/system/parts.css` | 부품과 메인 스타일 표현. HTML·React가 공유하며 역할 `--p-*`만 읽음 |
| `src/system/parts.js` | 시트·HTML 예시·HTML 배포의 공통 렌더러 |
| `src/system/react/` | 실제 React 컴포넌트, 입력 속성·상태·이벤트 |
| `src/system/behaviors.js` | 일반 HTML의 검색·탭·알림·초점 등 동작 |
| `assets/icons/` | 개별 아이콘 원본 |
| `문서/사전/` | 목적·사용 조건·패턴 정의 원문 |

토큰은 `원시 값 → 역할(--p-*)` 두 층이며, 두 층 모두 색·그러데이션·글꼴·글자 크기·굵기·줄 간격·자간·간격·크기·너비·모서리·테두리·선 모양·그림자·흐림·불투명도·비율·움직임·쌓임 순서·화면 폭 기준 스무 종류 파일로 묶는다. 글꼴 묶음(`--p-type-*`)이나 그러데이션처럼 여러 값을 합친 역할은 자기 종류의 원시 값과 다른 역할만 조합하며, 빌드가 그 종류 의존(그러데이션→색, 글꼴→글자 크기·굵기·줄 간격)을 계산해 배포 파일에 함께 싣는다. 역할 이름은 쓰임(`--p-control-size-sm`, `--p-panel-h-md`)이나 티셔츠 단계(`xs`~`xl`)로 짓고, 숫자 일련번호만으로 구분되는 역할은 두지 않는다. 부품은 이 한 곳에서 역할 `--p-*`만 가져다 쓰고 토큰을 선언하지 않는다. 이름 접두사가 파일 종류와 다르거나 역할이 다른 종류의 원시 값을 가리키면 빌드가 멈춘다. `parts.css`와 `src/styles/`가 원시 값(`--color-*` 등)을 직접 읽거나, 없는 역할을 읽거나, hex·px·ms·곡선·비율·그림자·변형·필터 값을 직접 쓰거나, `@media`에 역할에 없는 폭을 적으면 `build-system.mjs`가 멈춘다. 예외는 `scripts/tokens.mjs`의 `allowedToken`에 이유와 함께 적힌 구조 값(0, 100%, 가운데 맞춤 50%, fr, 직각 회전, 개수·배수)뿐이다. `--ds-bottom-nav-offset`처럼 `parts.css` 안에서 선언하고 쓰는 배치 조절값은 토큰이 아니며 부품 CSS 안에만 둔다.

배포본도 같은 경계를 따른다. 부품의 `css/<블록>.css`에는 규칙만 들어간다. `base.css`에는 공용 규칙이 읽는 역할 종류의 기본값(메인 스타일 원시 값)과 공용 규칙이 들어가며, 모든 항목에서 내용이 같아 여러 항목을 설치해도 서로 덮어쓰지 않는다. 역할 파일은 `styles/<스타일>/<종류>.css`로 나뉘어 부품이 실제로 읽는 종류만 원시 값으로 풀려 설치된다. 토큰 종류마다 `token-color`부터 `token-breakpoint`까지 레지스트리 항목 하나가 있고, 각 항목에 전용 표본과 JSON이 있다. 부품의 토큰 의존성은 그 부품 CSS가 실제로 읽는 `--p-*` 역할의 종류와 같아야 하며, 다르면 빌드가 멈춘다.

`build-system.mjs`는 공유 CSS와 자산을 내보내기용 데이터로 만든다. `build-registry.mjs`는 공식 shadcn Universal Items 형식의 레지스트리를 만든다. `~/design/...` 대상 경로가 명시되어 프레임워크 탐지나 `components.json` 없이 소스를 설치할 수 있다. `build-library.mjs`는 사전의 검색 정보와 문서를 만든다. 새 분류도 누락시키지 않고 기존 그룹 뒤에 추가한다.

`src/registry/registry.json`은 조회용 목록, `src/registry/r/*.json`은 실제 소스와 의존성이다. `src/ui/distribution.js`는 같은 레지스트리에서 코드 보기·ZIP·CLI 명령을 제공한다. 스타일×환경별 배포 파일 수를 독립 컴포넌트 수로 세지 않는다.

## 재사용 계약

토큰 → 아이콘·세부 표현 → 버튼·입력 등의 부품 → 필드·카드 → 검색 모듈 → 목록 레이아웃 → 실제 콘텐츠 화면을 연결한다. Pattern은 조합 규칙으로 연결하며 모든 구현이 바로 아래 계층만 사용해야 한다는 제약은 없다.

부품은 내부 표현과 동작을, 상위 조합은 배치·데이터·주요 행동을 맡는다. 카드의 제목·본문·행동 영역과 필드 라벨·설명을 공개한다. 독립 아이콘에는 다른 아이콘이나 프레임워크를 강제하지 않는다. 작은 부품 하나에 관련 없는 모듈을 포함하지 않는다.

HTML과 React의 컴포넌트 구현은 다르지만 CSS·토큰·아이콘 원본·ID를 공유한다. React에 HTML 문자열을 삽입하는 방식으로 지원을 대신하지 않는다. 필드의 ID 관계와 여러 탭 인스턴스의 독립 상태를 지킨다. 검색은 필터·빈 결과·복구·상세·저장 알림·목록 복귀를 제공하고, 저장은 프로젝트 콜백으로 연결한다.

HTML은 정적 표시와 추가 JavaScript 동작을 구분한다. 필요한 CSS·글꼴·자산·동작을 소스 묶음 또는 단독 파일로 제공한다. 코드 출처·버전·해시는 함께 남기며 프로젝트 편집 내용을 자동 덮어쓰는 갱신 기능은 없다.

## 스타일과 검증 상태

기존 9개 스타일은 제거하고 메인 프런트엔드 스타일 하나를 구축한다. 밝은 둥근 표면, 양각·음각, 제한된 유리 효과를 사용한다. 실제 화면과 부품이 같은 토큰을 쓴다. 단점과 보완, 적용 조건은 `문서/메인 스타일 명세.md`에 기록한다. 현재 상태는 Trial이다.

대표 흐름은 설치한 HTML과 Next.js에서 검증한다. 제작 예시와 다른 도서 콘텐츠, 빈 결과, 긴 한글, 복수 인스턴스, 초점 복귀, 좁은 화면을 포함한다. 보드·원문 탐색·ZIP은 Chromium·Firefox·WebKit에서도 확인한다. 테스트 파일과 실제 결과는 README와 `test-results/`에서 연결한다.

최종 완성은 항목 수나 테스트 수로 판단하지 않는다. 전체 사전 누락, 스타일별 대표 화면의 시각 품질, 새로운 과제에서의 적합한 선택과 조합, 사람의 보정 필요 여부가 남아 있다. 자동 기능 검사 통과와 시각적 승인, 실제 사용자 관찰을 구분한다.
