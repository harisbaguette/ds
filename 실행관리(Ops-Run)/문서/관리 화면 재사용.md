# 관리 화면 사용법

| ID | 기능 |
|---|---|
| `data-table` | 검색·필터·정렬·페이지 이동·선택 |
| `record-editor` | 상세 편집·저장·실패 재시도 |
| `admin-shell` | 제목·관리 메뉴·본문 배치 |
| `admin-page` | 목록과 편집기를 연결한 관리 화면 |

[자료 관리 화면](http://127.0.0.1:4173/#/system?detail=admin-page)의 ‘가져다 쓰기’에서 설치 명령과 오프라인 HTML을 받는다. 서버 연결을 생략하면 화면 안에서만 변경되며 새로 열면 초기화된다.

## 설치

로컬 서버를 켜고 사용할 프로젝트 폴더에서 필요한 환경의 명령을 실행한다.

```sh
npx shadcn@4.21.0 add http://127.0.0.1:4173/src/registry/r/pattove-main-admin-page-react.json
npx shadcn@4.21.0 add http://127.0.0.1:4173/src/registry/r/pattove-main-admin-page-html.json
```

URL의 `admin-page`를 다른 ID로 바꾸면 그 단위와 의존성만 설치한다. React는 `design/examples/main/admin-page.jsx`, HTML은 같은 위치의 `admin-page.html`에서 시작한다. 예시의 CSS 순서를 유지한다. React 런타임은 대상 프로젝트가 제공하며 표는 `@tanstack/react-table@8.21.3`을 사용한다. HTML은 `table-core.min.js`, `admin.js` 순서로 로드한다.

## 데이터와 저장 계약

레코드는 `{ id, title, status, owner, description }`다. `id`는 목록 내 고유하고 비어 있지 않은 문자열, `status`는 `statuses`의 value다. `title`은 필수이고 240자, `owner`는 120자, `description`은 4000자까지 입력한다.

- `loadRecords({ signal })`: 레코드 배열을 반환한다. 실패는 예외로 알린다. `signal`을 fetch에 전달하면 이전 요청을 취소할 수 있다. 취소를 지원하지 않아도 늦은 응답은 적용하지 않는다.
- `onSave(record)`: 저장된 레코드 또는 `undefined`를 반환한다. `undefined`는 전달한 입력의 저장 성공을 뜻한다. 실패는 예외로 알린다. `null`, 바뀐 ID, 빈 제목, 목록에 없는 상태는 성공 처리하지 않는다.
- `onSelectionChange(records)`: 선택된 자료를 받는다. 목록 갱신 시 사라진 자료의 선택은 제거한다. 검색·필터·정렬을 바꾸면 선택을 지우고 첫 쪽으로 이동한다.
- `onEdit(record)`: `DataTable`에 별도 편집 UI를 연결한다.

이 프로젝트에는 실제 서버 API가 없다. 소비 서비스에서 인증·권한·동시 편집 충돌·영구 저장을 제공해야 한다. 아래 `/api/requests`는 연결 예시 주소다.

## React

설치 예시의 스타일 import를 유지하고 `AdminPage`에 데이터를 연결한다. `loadRecords`는 컴포넌트 밖에 선언하거나 `useCallback`으로 참조를 유지한다. 함수가 바뀌면 목록을 다시 읽는다.

```jsx
async function loadRequests({ signal }) {
  const response = await fetch('/api/requests', { signal });
  if (!response.ok) throw new Error('자료를 불러오지 못했습니다.');
  return response.json();
}

async function saveRequest(record) {
  const response = await fetch(`/api/requests/${encodeURIComponent(record.id)}`, {
    method: 'PUT',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify(record),
  });
  if (!response.ok) throw new Error('저장하지 못했습니다. 다시 시도해 주세요.');
  if (response.status === 204) return;
  return response.json();
}

<AdminPage
  title="고객 요청"
  titleLabel="요청"
  ownerLabel="담당팀"
  initialRecords={[]}
  statuses={[{ value: 'open', label: '접수' }, { value: 'closed', label: '해결' }]}
  loadRecords={loadRequests}
  onSave={saveRequest}
/>
```

`initialRecords`는 초기값이다. 서버 없이 사용할 때는 여기에 배열을 넘기고 `loadRecords`를 생략한다. 외부에서 목록을 계속 제어하려면 `DataTable records={...}`와 `RecordEditor`를 조합한다. `DataTable`의 `loading`, `error`, `onRetry`로 읽기 상태를 표시한다.

`RecordEditor`는 선택한 레코드별로 마운트하고 `onClose`에서 제거한다. 부모가 같은 편집기를 다른 자료로 바꿀 때는 `key={record.id}`를 둔다. 저장에 필요한 `onSave`가 없으면 입력을 유지하며 연결 오류를 표시한다.

`TableToolbar`와 `TablePagination`은 `data-table` 설치에 포함되며 같은 TanStack table 인스턴스로 조합할 수 있다.

## HTML

컨테이너에 `class="ds" data-style="main"`을 두고, 인스턴스마다 다른 prefix를 쓴다.

```js
const root = document.querySelector('#management');
root.innerHTML = Pattove.admin.renderPage('requests', {
  title: '고객 요청', titleLabel: '요청', ownerLabel: '담당팀',
  records: [],
  statuses: [{ value: 'open', label: '접수' }, { value: 'closed', label: '해결' }],
});
const controller = Pattove.admin.connect(root, {
  loadRecords: loadRequests,
  onSave: saveRequest,
});

await controller.reload(); // 필요할 때 다시 읽기
controller.replaceRecords(records); // 이미 받은 배열로 교체
```

`connect`는 `loadRecords`가 있으면 첫 목록을 자동으로 읽는다. `reload()`는 적용 성공 시 `true`, 실패·취소·편집 중이면 `false`를 반환한다. `replaceRecords`는 편집 중 호출하면 오류를 낸다. 요청 중 직접 자료를 교체하면 이전 요청의 응답은 폐기한다. 저장 완료는 `pattove:admin-saved` 이벤트로도 받을 수 있다.

편집기만 사용할 때:

```js
root.innerHTML = Pattove.admin.renderEditor('request-editor');
const editor = Pattove.admin.connectEditor(root, {
  titleLabel: '요청',
  statuses: [{ value: 'open', label: '접수' }, { value: 'closed', label: '해결' }],
  onSave: saveRequest,
  onClose: () => { /* 편집 종료 처리 */ },
});
editor.open(record, document.querySelector('#edit-button'));
```

단독 편집기는 `onSave`를 제공해야 한다. `open`의 두 번째 인수는 닫은 뒤 초점을 돌릴 요소다.
