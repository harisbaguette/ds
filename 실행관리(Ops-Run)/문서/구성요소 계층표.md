# 디자인 시스템 구성요소 계층표

작성일: 2026-09-22. [디자인 시스템 정의](<디자인 시스템 정의.md>)의 아토믹 단위 원칙을 실제 구성요소 목록으로 펼친 표다. 디자인 시스템 한 벌을 만들 때 어떤 구성요소가 있어야 하고, 각 구성요소가 어느 층에 서는지를 한눈에 보기 위한 색인이며, 항목별 상세 명세와 사례는 [패턴 사전 색인과 사용법](<패턴 사전 색인과 사용법.md>)의 해당 ID를 따른다. 사전의 아토믹 계층(ATM)·토큰(TOK)·모듈 블록(MOD)·상태(STT)·배치(LAY)·탐색(NAV)·행동(ACT)·상태 피드백(STA)·사용자 흐름(FLW) 분류와 대조해 빠진 구성요소를 채웠다. 사전 대조 뒤에는 외부 디자인 시스템·토큰 표준·공공 디자인 시스템·부품 라이브러리·AI 패턴·플랫폼 지침을 조사해 빠진 종류를 더 채웠다. 그때 확인한 외부 자료와 신뢰도는 [레퍼런스 출처 대장](<레퍼런스 출처 대장.md>)에 있다.

**이 프로젝트는 구성요소를 Token → Primitive → Atom → Molecule → Module → Pattern → Template → Page의 여덟 구분으로 정리한다.** 이는 역할을 찾기 위한 분류이며, 모든 코드를 바로 아래층만 거쳐 조립하라는 뜻은 아니다. 상위 구성은 필요한 토큰·아이콘·하위 부품을 직접 사용할 수 있고, 재사용하는 하위 부품은 특정 페이지에 의존하지 않게 한다. Pattern은 여러 층에 적용되는 사용 규칙으로 연결한다.

각 항목을 개별로 가져오는 목표와 HTML 지원 조건은 [디자인 시스템 정의](<디자인 시스템 정의.md>)를 따른다. 분류상의 단위가 파일·패키지의 단위와 같을 필요는 없으며, 실제 의존성과 부모가 필요한 부분은 구현 명세에 표시한다.

## 층을 나누는 기준

| 층 | 뜻 | 쪼개는 판정 | 사전의 분류 |
|---|---|---|---|
| 0. Token | 모든 층이 공유하는 디자인 값. 그 자체로는 화면에 보이지 않는다 | 값 하나를 바꾸면 여러 부품이 함께 바뀌는가 | [TOK](<사전/57-TOK-디자인 토큰 사전.md>) |
| 1. Primitive | 토큰을 처음으로 눈에 보이게 만든 최소 표현 | 역할은 있으나 아직 상호작용이 없는가 | [VIS](<사전/01-VIS-스타일을 구성하는 공통 기준.md>), [TYP](<사전/31-TYP-타이포그래피와 정밀 조판.md>), [ICO](<사전/54-ICO-아이콘·기호 사전.md>), [IMG](<사전/32-IMG-이미지·시각 자산의 사용 방식.md>), [FX](<사전/40-FX-배경·재질·장식 효과의 표현 도구.md>) |
| 2. Atom | 더 쪼개면 뜻이 사라지는 최소 UI 부품 | 혼자서도 쓰이고 상태를 가지는가 | [ATM](<사전/55-ATM-아토믹 디자인 계층 — 원자·분자·유기체·템플릿·페이지.md>)(원자), [ACT](<사전/04-ACT-행동과 겹쳐 열리는 영역.md>), [INP](<사전/05-INP-입력과 폼.md>) |
| 3. Molecule | 원자 몇 개를 묶어 한 가지 작은 일을 하는 부품 | 묶음을 풀어도 각 원자가 따로 쓸모가 있는가 | [ATM](<사전/55-ATM-아토믹 디자인 계층 — 원자·분자·유기체·템플릿·페이지.md>)(분자), [INP](<사전/05-INP-입력과 폼.md>), [NAV](<사전/03-NAV-탐색과 현재 위치.md>) |
| 4. Module / Organism | 분자와 원자를 모아 한 기능이나 한 구역을 완성한 단위 | 데이터와 동작을 연결해야 비로소 뜻이 생기는가 | [ATM](<사전/55-ATM-아토믹 디자인 계층 — 원자·분자·유기체·템플릿·페이지.md>)(유기체), [MOD](<사전/56-MOD-페이지 구역 모듈 블록 사전.md>), [DAT](<사전/06-DAT-검색·목록·데이터 작업.md>) |
| 5. Pattern | 여러 부품이 함께 움직이는 규칙. 특정 부품이 아니라 사용 방법 | 같은 문제를 다른 부품 조합으로도 풀 수 있는가 | [FLW](<사전/14-FLW-실제 화면을 연결하는 사용자 흐름.md>), [STA](<사전/07-STA-상태·피드백·복구.md>), [PRF](<사전/46-PRF-체감 속도와 기다림 설계.md>), [SRH](<사전/15-SRH-검색과 발견의 세부 패턴.md>) 등 |
| 6. Template | 실제 내용 없이 자리와 크기만 잡은 화면 골격 | 내용을 바꿔도 구조가 그대로 남는가 | [LAY](<사전/02-LAY-화면 골격과 배치.md>), [ATM](<사전/55-ATM-아토믹 디자인 계층 — 원자·분자·유기체·템플릿·페이지.md>)(템플릿) |
| 7. Page | 진짜 내용과 데이터를 넣은 완성 화면 | 실제 글과 사진으로 길이·빈칸·최악 경우를 시험했는가 | [ATM](<사전/55-ATM-아토믹 디자인 계층 — 원자·분자·유기체·템플릿·페이지.md>)(페이지), [FLW](<사전/14-FLW-실제 화면을 연결하는 사용자 흐름.md>) |

## 사전의 다섯 구분과 여덟 층의 대응

패턴 사전은 항목마다 종류를 기준·부품·구성·모듈·흐름 다섯 가지로 적는다. 이 표는 그 다섯 가지가 위 여덟 층의 어디에 서는지를 잇는다. 사전에서 항목을 꺼낼 때 어느 층의 부품으로 쓸지, 반대로 이 계층표의 한 칸을 채울 때 사전의 어느 종류를 찾을지를 이 표로 판단한다.

| 사전의 종류 | 대응하는 층 | 이어 읽는 방법 |
|---|---|---|
| 기준 | 0. Token, 1. Primitive | 토큰은 값으로 참조하고, 아이콘·구분선 같은 최소 표현은 화면에 직접 놓거나 다른 부품 안에서 쓴다 |
| 부품 | 2. Atom, 3. Molecule | 따로 쓰거나 교체하는 단위. 상태를 가지면 원자, 원자를 묶어 한 가지 일을 하면 분자 |
| 구성 | 5. Pattern | 특정 부품이 아니라 배치·상호작용 문제의 해법이므로, 다른 부품 조합으로도 같은 문제를 푼다 |
| 모듈 | 4. Module / Organism | 부품과 구성을 결합한 기능·콘텐츠 영역. 데이터와 동작을 연결해야 뜻이 생긴다 |
| 흐름 | 7. Page | 여러 상태와 화면을 거쳐 일을 끝내는 과정이라, 실제 내용을 넣은 완성 화면에서만 검증된다 |

6. Template은 사전의 다섯 구분에 대응하는 종류가 없다. 내용 없이 자리와 크기만 잡은 골격이라 [LAY](<사전/02-LAY-화면 골격과 배치.md>) 분류의 부품과 모듈로 조립해 쓴다.

## 실무에서 특히 분리해 둘 다섯 영역

Token, Icon, Component(Atom·Molecule), Module, Pattern 다섯 영역은 서로 다른 속도로 바뀌고 다른 사람이 관리하므로 저장 위치와 문서를 분리한다.

| 영역 | 바뀌는 속도 | 분리하는 이유 |
|---|---|---|
| Token | 가장 느림 | 값 하나가 전체에 퍼지므로 변경 승인 절차가 필요하다 |
| Icon | 느림 | 세트 단위로 교체되며 그리드·선 굵기 규칙이 따로 있다 |
| Component | 보통 | 코드와 함께 배포되며 API·상태·접근성 시험을 가진다 |
| Module | 빠름 | 제품 기능에 따라 늘어나고 데이터 연결이 필요하다 |
| Pattern | 제품마다 다름 | 부품이 아니라 사용 규칙이므로 코드가 아닌 문서와 예시로 관리한다 |

Card 같은 것은 컴포넌트이고, 검색 → 필터 → 결과처럼 여러 컴포넌트가 함께 동작하는 규칙은 Pattern으로 따로 관리한다. 같은 Pattern을 여러 스타일의 부품으로 구현할 수 있어야 하며, 이것이 [디자인 시스템 정의](<디자인 시스템 정의.md>)에서 말하는 스타일별 디자인 시스템의 전제다.

이 표를 채우며 확인한 외부 자료와 그 신뢰도는 [레퍼런스 출처 대장](<레퍼런스 출처 대장.md>)에 정리해 두었다.
