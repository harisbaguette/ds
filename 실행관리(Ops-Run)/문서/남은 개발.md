# 남은 개발

| 범위 | 끝내야 할 내용 | 완료 판단 |
|---|---|---|
| 사전의 미구현 항목 | 용도별 우선순위를 정해 실제 부품·흐름을 구현하고 HTML·React 소스와 연결 | 사전 ID에서 실행·재사용 가능한 구현으로 이동하며 소비 프로젝트 검사 통과 |
| 원문 대조 | `coverage`의 `needsSourceReview` 항목마다 원문·적용 범위·예외 확인 | 근거 없는 ‘대조’ 표기를 추가하지 않고 항목별 출처와 적용 조건 확보 |
| 상세 규격 | 각 항목의 금지 상황·상태·접근성·지원 환경·호환성을 구체화 | 한 줄 정의만으로 구현 판단을 대신하지 않음 |
| 스타일과 자산 | 새 스타일별 대표 화면, 아이콘·일러스트·사진 규칙과 독립된 토큰 세트 제작 | 실제 콘텐츠의 목록·폼·상세·오류 화면에서 시각 검토 |
| AI의 전체 작업 | 화면 JSON의 지원 부품을 넓히고, 목적 해석→선택→콘텐츠 조합→평가→수정을 다양한 실제 과제로 평가 | 검색 점수나 DOM 검사 통과를 디자인 승인으로 간주하지 않고 과제별 결과 비교 |
| 사용자 평가 | 실제 사용자의 이해·작업 성공·오류 복구와 시각 선호 확인 | 관찰 결과를 부품 규격과 프로젝트 선택 기록에 반영하고 Stable 검토 |
| 플랫폼 확장 | 네이티브 대상 플랫폼과 인쇄물 규격을 정해 별도 구현 | 해당 기기·출력물에서 검증; 웹 미리보기로 대체하지 않음 |
| 배포 운영 | 원격 CI 결과 확인, 서명된 실행 배포물과 필요한 업데이트 절차 마련 | 대상 운영체제의 새 PC에서 설치·이동·실행·복구 검증 |
| 저장소 이력 | 과거 대용량 이미지 중 보존·제거 범위 결정 | 백업과 공동 작업자 이전을 포함해 이력 정리 |
| 개발 의존성 | 공식 수정본이 없는 `braces` 취약점 추적 | shadcn 설치 경로를 유지하면서 수정본 적용과 소비 프로젝트 검사; [현재 제한](<배포와 저장소 관리.md#개발-도구의-미해결-의존성>) |

현재 대상을 조회하려면 `npm run system -- coverage`를 사용합니다. 구현 상태와 원문 확인 상태는 별개이며, 기준 문서와 이미지 자산을 부품 수에 합산하지 않습니다. 파일 목록과 버전이 바뀌면 다시 조회합니다.

검색·소스 재사용·화면 검사·프로젝트 선택 기록은 [시스템 사용과 확장](<시스템 사용과 확장.md>), 패키지와 설치본 갱신은 [배포와 저장소 관리](<배포와 저장소 관리.md>)를 참고합니다.
