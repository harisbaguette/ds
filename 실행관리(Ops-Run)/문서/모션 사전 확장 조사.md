# 모션 사전 확장 조사

모션은 확장이 필요하다. **기존 사전과 모션 메뉴를 연결하고, 실행 예제 20개를 우선 보강하는 안**을 제안한다. 별도 개념으로 추가할 후보는 경로 이동과 연결선 흐름광 2개다. 아래 분류·우선순위·구현 조건은 공식 자료와 현재 프로젝트를 대조한 제안이다.

## 현재 부족한 부분

| 영역 | 현재 내용 | 보강할 부분 |
|---|---|---|
| 모션 메뉴 | 7개 분류, 실행 예제 12개, 외부 레퍼런스 8개 | 퇴장, 상태 변화, 레이아웃·화면 전환, 텍스트·숫자 예제 |
| ANM 사전 | 움직임과 시각적 전환 41개 | 22개가 모델 지식 확장 `[MK]`으로 등록되어 있어 공식 원문과 사용 조건 보강 필요 |
| MOT 사전 | 모바일 조작과 움직임 25개 | 드래그·관성·중단 가능한 전환을 모션 메뉴에서도 찾게 연결 |
| FX 사전 | 배경·재질·장식 효과 35개 | 마키·틸트·스포트라이트·보더 빔 등의 실행 예제 연결 |

현재 예제는 등장 2개, 반응·조작 2개, 배경 1개, 텍스트 1개, 스크롤 1개, 로딩 3개, 3D 2개다. 스프링·공유 요소·목록 재배치·마키·타이핑·카운트업은 이미 사전 항목이므로, 기존 ID를 참조하는 예제로 확장할 수 있다. 모션 데이터에는 현재 사전 ID를 연결하는 필드가 없다.

근거: [모션 데이터](../src/data/motion.js), [ANM 사전](<사전/33-ANM-움직임과 시각적 전환.md>), [MOT 사전](<사전/13-MOT-모바일 조작과 움직임.md>), [FX 사전](<사전/40-FX-배경·재질·장식 효과의 표현 도구.md>).

## 찾기와 선택에 필요한 분류

모션 메뉴의 분류는 **등장·퇴장 / 상태·피드백 / 레이아웃·화면 전환 / 텍스트·숫자 / 스크롤 / 포인터·제스처 / 배경·장식 / 3D**를 제안한다. 각 예제에는 대표 분류 하나와 관련 사전 ID를 붙인다.

진입·클릭·초점·스크롤·자동 반복은 시작 조건 필터로 둔다. CSS·JavaScript·SVG·Canvas·WebGL과 라이브러리 이름은 구현 방식으로 표시한다. 예를 들어 ‘카드→상세’는 사용 목적이고 View Transition API는 구현 선택지다. [MDN View Transition API](https://developer.mozilla.org/en-US/docs/Web/API/View_Transition_API).

Fade의 상하좌우 방향, 속도, 지연은 같은 예제의 설정값으로 묶는다. 검색 별칭에 `fade`, `slide`, `reveal`, `stagger` 같은 통용 용어를 함께 둔다.

## 구현 전에 해결할 부분

현재 [코드 내보내기](../src/ui/motion.js)는 HTML·CSS 예제를 JSX로 바꾸는 구조다. 상태 관리, 드래그, 스프링 예제를 추가하려면 환경별 실행 코드와 의존성, 초기화·해제 동작을 내보내는 기능도 확장해야 한다. 화면 미리보기와 복사한 결과가 같은 동작을 하도록 설계한다.

움직임 줄이기는 효과마다 대체 표현을 정한다. Motion의 `reducedMotion="user"`는 transform·layout을 줄여도 opacity·배경색 애니메이션은 남길 수 있다. 정지 상태가 필요한 반복 효과는 별도로 처리한다. [Motion 접근성](https://motion.dev/docs/react-accessibility).

자동으로 시작하고 5초를 초과하며 다른 콘텐츠와 함께 표시되는 이동·깜빡임·스크롤 정보에는 필수 동작 예외를 제외하고 일시정지·중지·숨김 수단이 필요하다. 자동 갱신 정보에는 별도 조건이 있고 5초 예외가 없다. 입력으로 시작하는 비필수 모션을 끌 수 있게 하는 기준은 AAA다. 두 기준을 구분해 사전에 적는다. [W3C 2.2.2](https://www.w3.org/WAI/WCAG22/Understanding/pause-stop-hide), [W3C 2.3.3](https://www.w3.org/WAI/WCAG22/Understanding/animation-from-interactions.html).

성능은 `transform`·`opacity`를 우선 검토하되, 실제 기기에서 확인한다. 높이·마스크·배경 변화는 레이아웃·페인트 비용을 따로 본다. 작은 데모의 비용을 전체 화면 배경의 비용으로 일반화하지 않는다. [web.dev 애니메이션 성능](https://web.dev/articles/animations-guide).

실행 예제 제작과 실제 브라우저·기기 검증은 남아 있다. 추가 순서는 **사전 연결·공식 근거 보강 → A 예제 10개 → B 예제 10개 → 신규 개념 2개**를 제안한다.
