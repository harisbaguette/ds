# 배포와 저장소 관리

## 소스 패키지

`실행관리(Ops-Run)`에서 실행합니다.

```sh
npm ci
npm run build
npm run test:all
npm run package:source -- --out ./test-results/releases/pattove-source.zip
```

ZIP에는 앱 소스·원본 자산·문서·검사·실행 스크립트가 들어갑니다. Windows 실행 파일이 현재 폴더에 있으면 함께 넣습니다. `.git`, 개인 MCP 설정, 캐시, `node_modules`, 임시 검사 결과와 시안은 포함하지 않습니다. 포함 파일은 `--list`로 먼저 확인할 수 있습니다. `release-manifest.json`은 각 파일의 해시를, ZIP 옆 `.sha256` 파일은 전체 ZIP의 해시를 제공합니다.

받은 PC에는 Node.js 22 이상이 필요합니다. 압축을 푼 후 `실행관리(Ops-Run)`에서 `npm ci`를 실행하고 해당 운영체제의 실행 파일을 엽니다. Windows 실행 파일이 없으면 `npm run build:launcher`로 만듭니다. AI 도구를 연결하려면 `npm run configure:mcp`를 실행한 뒤 클라이언트를 다시 시작합니다.

## Git 용량

앱만 전달할 때는 소스 패키지를 사용합니다. 개발용 새 복사본은 다음 명령으로 현재 버전만 받습니다.

```sh
git clone --depth 1 --no-tags <repository-url>
```

이미 공유한 과거 이미지 이력을 줄이려면 별도 복제본에서 제거할 경로와 필요한 태그를 먼저 정해야 합니다. 이력 재작성은 커밋 ID를 바꾸므로 공동 작업자의 브랜치와 배포 참조도 함께 옮겨야 합니다. 원본 자산은 삭제 대상과 구분하고, 이력 재작성 전에 새 복사본에서 빌드·전체 검사·이미지 다운로드를 확인합니다.

## 버전 갱신

`package.json`, `package-lock.json`, `src/system/registry.js`의 버전을 함께 갱신하고 다시 빌드합니다. 소비 프로젝트에서 `npm run system -- diff --project <directory>`로 설치본의 로컬 수정과 갱신 가능 여부를 확인한 뒤, 새 폴더로 내보낸 소스와 비교합니다. 사용 중인 파일을 덮어쓰는 자동 마이그레이션은 제공하지 않습니다.

Trial 부품은 시각·사용성·소비 프로젝트·접근성 검토가 끝난 뒤 Stable로 올립니다. Deprecated 부품에는 대체 ID를 지정합니다. 삭제한 부품을 사용하는 프로젝트는 `diff`에서 `unavailable`로 나타납니다.

## 개발 도구의 미해결 의존성
