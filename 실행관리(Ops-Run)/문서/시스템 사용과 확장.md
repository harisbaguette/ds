# 시스템 사용과 확장

명령은 `실행관리(Ops-Run)`에서 실행합니다. 소스나 토큰을 수정한 뒤에는 `npm run build`를 실행합니다.

## 찾기와 가져오기

```sh
npm run system -- search "로그인" --implemented
npm run system -- get INP-04 --env react
npm run system -- recipes
npm run system -- plan settings-form
npm run system -- export --id textarea --id select --env react --out ./my-form
npm run system -- compose --recipe article-page --out ./my-article
```

검색 결과의 점수는 후보를 찾는 데 사용합니다. 목적·콘텐츠·지원 환경을 확인해 선택하세요. `get`은 사전 ID와 구현 ID 모두 받으며 설치 명령·의존성·입력·이벤트 계약을 반환합니다. 일반 HTML과 React를 지원하며 모바일 네이티브는 지원하지 않습니다.

내보내기는 새 폴더에만 씁니다. HTML 조합의 `index.html`은 파일로 직접 열 수 있습니다. React 조합은 `page.jsx`에서 시작하며 대상 프로젝트에 React와 결과에 표시된 npm 의존성이 필요합니다. `--recipe`는 기본 예시를, `--spec`은 작성한 콘텐츠를 사용합니다.

`search-filter-results`, `admin-edit-save`, `settings-form`, `login-form`, `input-result`, `comparison`, `article-page` 조합을 제공합니다. 로그인과 저장에는 소비 프로젝트의 인증·저장 서비스를 연결해야 합니다.

## 실제 콘텐츠로 화면 만들기

```sh
npm run system -- screen-contract
npm run system -- validate-screen --spec "문서/예시/수업 신청.json"
npm run system -- compose --spec "문서/예시/수업 신청.json" --out ./application
npm run system -- evaluate --project ./application
```

화면 JSON에는 `version: 1`, `intent`, `title`, `sections`를 넣습니다. 각 섹션은 고유 `id`, 구현 이름 `component`, 실제 내용 `props`를 갖습니다. `screen-contract`가 JSON Schema와 예시를 반환합니다. 지원하는 조합은 입력·제출, 이름과 값 요약, 비교, 본문·목차, 접고 펼치기, 금액 계산, 로그인, 프로필 설정입니다. 한국어와 `main` 스타일을 지원합니다.

잘못된 필드·중복 ID·지원하지 않는 속성은 파일 생성 전에 거부합니다. 문자열은 텍스트로 출력합니다. 비밀번호와 인증 토큰을 명세에 넣지 마세요. 이전 결과를 고칠 때는 `pattove.screen.json`을 수정하고 새 폴더로 내보냅니다.

HTML은 생성된 `bindings.js`에서 `window.pattoveScreenHandlers[섹션 ID]`에 함수를 연결합니다. React는 생성된 `Screen`에 `handlers={{ [섹션 ID]: 함수 }}`를 전달합니다. 제출 함수는 `(values, { signal })`을 받고 Promise를 반환합니다. 비교 섹션의 함수는 선택한 항목을 받습니다.

`data-form`의 필드 종류는 `text`, `email`, `password`, `tel`, `url`, `number`, `date`, `time`, `textarea`, `select`, `checkbox`입니다. 제출 시 오류 요약에서 해당 입력으로 이동하고, 서버가 거부해도 입력은 유지합니다. 서버의 필드 오류는 `throw { fieldErrors: { email: '다른 이메일을 입력하세요.' } }`처럼 전달합니다. 체크박스 값은 boolean, 나머지 입력값은 문자열입니다. 서버에서도 형식·권한을 검사해야 합니다.

오류 요약은 [GOV.UK Error summary](https://design-system.service.gov.uk/components/error-summary/)의 입력 연결·초점 원칙, 이름과 값 요약은 [GOV.UK Summary list](https://design-system.service.gov.uk/components/summary-list/)의 정의 목록을 따릅니다. 표 형태의 비교 데이터에는 `summary-list`를 사용하지 않습니다.

## 저장과 로그인 연결

React의 `SettingsForm`은 `onSave(values, { signal })`, `LoginForm`은 `onAuthenticate(values, { signal })`를 받습니다. 반환된 Promise가 성공한 뒤에만 완료를 표시합니다. 실패하면 값을 유지하며 같은 버튼으로 재시도합니다.

HTML에서는 초기화된 폼의 이벤트에 응답합니다.

```js
document.querySelector('[data-async-form="settings"]')
  .addEventListener('pattove:submit', event => {
    const { values, signal, respondWith } = event.detail;
    respondWith(fetch('/api/profile', {
      method: 'POST',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify(values),
      signal
    }).then(response => {
      if (!response.ok) throw new Error('저장 실패');
    }));
  });
```

`respondWith`는 이벤트 처리 중 한 번 호출합니다. 호스트가 응답하지 않으면 성공으로 표시하지 않습니다. 사용자 입력은 텍스트로 전달하고, 파일 업로드는 서버에서도 형식·크기·권한을 확인하세요.

`Pagination`의 `onPageChange`와 HTML의 `pattove:pagechange`는 페이지 번호를 전달합니다. 실제 목록 읽기는 호스트에서 연결합니다. `Comparison`의 `onChoose`와 `pattove:choose`는 선택 결과를 전달하며 결제를 수행하지 않습니다.

## 프로젝트별 선택과 화면 검사

```sh
npm run system -- configure --project ./my-project --env html --recipe settings-form --intent "프로필을 수정하고 저장"
npm run system -- record --project ./my-project --id dialog --decision accept --reason "삭제 전 확인이 필요함"
npm run system -- profile --project ./my-project
npm run system -- plan --project ./my-project
npm run system -- compose --project ./my-project --out ./new-screen
npm run system -- evaluate --project ./new-screen
npm run system -- evaluate --url http://127.0.0.1:3000
```

프로젝트 폴더의 `pattove.project.json`에 목적·환경·조합·채택하거나 제외한 이유를 저장합니다. AI는 계획과 이 파일을 함께 읽고 다음 선택에 반영합니다. 자동으로 취향을 추정하거나 검사 통과를 사용자 승인으로 기록하지 않습니다.

화면 검사는 320·768·1440px 화면, 깨진 이미지와 리소스, 실행 오류, 이름 없는 조작 요소, 중복 ID와 끊어진 접근성 참조를 확인합니다. 결과 폴더에 스크린샷과 `report.json`을 남기며, 문제가 있으면 종료 코드 1을 반환합니다. 수정 후 같은 명령으로 다시 검사합니다. React는 실행 중인 로컬 주소를 사용합니다. 자동 검사 이후 읽는 순서·주 행동·색 대비·스크린리더·실제 콘텐츠의 실패와 복구를 확인해야 합니다.

## MCP 연결

```sh
npm run configure:mcp
```

현재 폴더 위치로 두 MCP 설정을 갱신한 뒤 클라이언트를 다시 시작합니다. 다른 PC로 옮겼을 때도 같은 명령을 실행합니다. 기존의 다른 MCP 설정은 유지됩니다. 생성된 `.mcp.json`과 `.codex/config.toml`에는 PC별 경로가 들어가므로 Git에 포함하지 않습니다.

`pattove-system`은 검색, 부품 계약, 조합 목록·계획, 분야별 지원 범위, 화면 명세 계약과 검증을 제공합니다. `get_screen_contract`로 스키마를 받고 `validate_design_screen`으로 작성한 명세를 검사합니다. 일러스트 검색·미리보기·내보내기는 `pattove-illustrations`를 사용합니다. 시스템 MCP는 읽기 전용입니다. 프로젝트 파일 생성은 CLI로 실행합니다.

## 갱신과 지원 상태

```sh
npm run system -- diff --project /path/to/consumer
npm run system -- coverage
npm test
npm run test:all
```

`diff`는 설치 당시 해시와 현재 파일을 비교해 누락·로컬 수정·업데이트 가능 여부를 반환합니다. 수정한 파일을 덮어쓰지 않습니다. 새 소스를 별도 폴더로 내보내고 변경 사항을 비교해 반영하세요.

`coverage`는 규칙 문서, 이미지 자산, 실제 구현, 미구현을 구분하고 원문 대조가 필요한 항목을 표시합니다. 이 수치를 전체 완성률로 해석하지 않습니다. 현재 부품은 Trial입니다. Stable로 올리려면 지원 환경의 조합 검사와 실제 사용자 관찰이 필요하며, Deprecated 항목에는 대체 ID가 있어야 합니다.

`npm test`는 빌드와 핵심 검사를, `npm run test:all`은 전체 자동 검사를 실행합니다. 실행기 검사는 서버를 잠시 종료하므로 `npm run test:launcher`로 별도 실행합니다. 세 운영체제의 CI 설정은 저장소에 포함되며, 해당 실행 결과가 나오기 전에는 다른 운영체제 검증 완료로 간주하지 않습니다.

대화상자는 [HTML dialog](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/dialog), 팝오버는 [Popover API](https://developer.mozilla.org/en-US/docs/Web/API/Popover_API/Using), 검색 가능한 선택은 [WAI-ARIA Combobox](https://www.w3.org/WAI/ARIA/apg/patterns/combobox/)의 동작을 기준으로 사용합니다.
