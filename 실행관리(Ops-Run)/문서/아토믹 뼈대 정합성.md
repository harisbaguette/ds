# 아토믹 뼈대 정합성

2026-09-26. [디자인 시스템 정의](<디자인 시스템 정의.md>) 전체의 목표와 요구사항을 기준으로 현재 구현을 대조한다. 원래 목표는 그대로 유지한다. 현재 상태는 **0.3.0 / Trial**, 대표 흐름의 구현·재사용 검증 단계다.

이전 작업은 테마를 나열한 화면, 글 위주의 사전, 단독 HTML 다운로드만으로 목표를 충족한 것처럼 다뤘다. 정의서가 요구하는 것은 목적에서 선택해 실제 프로젝트에 가져오고 조합·검수하는 연결이며, 기술 검사 통과만으로 디자인 전체를 완성 처리할 수 없다.

## 기준별 대조

| 정의서 기준 | 현재 반영 | 남은 범위 |
|---|---|---|
| 1. 작은 유용한 단위와 조합 | 개별 아이콘·토큰·부품과 카드/필드의 공개 부분. 의존성을 포함한 소스 설치·ZIP | 전체 사전의 모든 구현 |

| 7. 실제 결과 검증 | 별도 소비 프로젝트, 다른 콘텐츠, 오프라인 HTML, 키보드·초점·반응형·3브라우저 | 모든 스타일의 시각 승인·실사용 관찰·새 과제 평가 |

## 현재 직접 사용할 수 있는 경로

1. 메인 스타일 시트에서 실제 부품의 상태를 비교한다.
2. 사전의 시각 예시나 목적 필터로 같은 구현을 찾는다.
3. HTML·React를 선택하고 소스 파일, CLI 명령 또는 의존성이 포함된 ZIP을 받는다.
4. 설치한 부품을 프로젝트 데이터와 행동에 연결한다.

주 메뉴는 스타일·사전 두 개다. 계층표·문서는 필요한 항목의 설명에서 연결한다. 모든 원문과 기존 주소·저장 항목은 보존한다. 새 사전 분류도 생성기에 자동 포함하되 원문 수록을 구현 완료로 표시하지 않는다.

검색 예시의 저장은 화면 안의 동작이며 실제 영구 저장 서비스는 아니다. React의 `onSave` 또는 HTML의 사용자 이벤트로 프로젝트 행동을 연결한다. HTML의 정적 표시, 동작에 필요한 JavaScript, 단독 파일·오프라인 사용을 구분한다.

## 검증 근거

| 파일 | 확인 대상 |
|---|---|
| `tests/source-consumers.cjs` | 공식 CLI로 새 HTML·React 프로젝트에 설치, Next.js 실행, 다른 도서 콘텐츠, 검색·복구·상세·저장 콜백·초점 복귀, 독립 탭, 네트워크 차단 HTML, 개별 SVG |
| `tests/atlas.cjs` | 세 브라우저의 시트·시각 사전·부품 분류·실제 ZIP 내용·모바일 |
| `tests/system.cjs`, `tests/system-audit.cjs` | 최소 단위·하위 조합·독립 HTML·스타일별 공유 CSS·누락 자산·중복 ID |
| `tests/design-audit.cjs`, `tests/visual.cjs` | 글자 대비·터치 영역·넘침·자산·글꼴·실제 화면 캡처 |
| 기존 shell·styles·outer·library 검사 | 주소·히스토리·저장·전체 원문 검색·문서 연결 회귀 |

메인 스타일 변경 후 `tests/styles.cjs`에서 이전 스타일의 목록·CSS·설치 파일 제거, 옛 주소·저장 항목의 이행, 대비, 눌림·초점·비활성 상태, 고대비·움직임 감소, 320–1920px 화면을 확인했다. 측정된 대비는 본문 10.84:1, 보조 글자 5.19:1, 입력 경계 3.18:1이다. 측정값과 실제 캡처는 `test-results/main-style/`에 있다.

검사 결과와 캡처는 `test-results/`에 남긴다. 검사는 실행한 소스와 조건의 근거이며 전체 품질 보증이 아니다. 스타일별 시각 품질, 설명 없는 이해, 사람의 디자인 보정이 불필요한지는 별도 평가 대상이다. 정의서의 100% 목표를 현재 대표 부품 수로 바꾸지 않는다.
