# 일러스트 사용과 관리

아이콘 탭에서 검색하고 PNG·WebP를 받습니다. 원하는 그림은 상세에서 ‘팩에 담기’를 누른 뒤 ‘선택한 그림 받기’로 묶습니다. 기본 UI와 분류별 팩, 현재 페이지도 내려받을 수 있습니다. ZIP에는 이미지, HTML, React 컴포넌트, 파일 해시 목록이 포함됩니다.

## AI에서 사용

프로젝트 폴더에서 실행합니다. 검색 결과는 기본 20개이며 한국어·영어·ID를 지원합니다.

~~~sh
npm run icons -- search 검색
npm run icons -- get ICO-62
npm run icons -- packs
npm run icons -- export --id ICO-62 --id material:yard --out ./my-icons
npm run icons -- export --pack core-ui --format webp --size 192 --out ./ui-icons
~~~

출력 폴더는 새 폴더여야 합니다. 기존 프로젝트 파일을 덮어쓰지 않습니다. 전체 파일이 필요하면 export --all --out ./all-icons를 사용합니다. 선택한 ID는 유지하며 같은 그림을 공유하는 항목의 이미지 파일은 한 번만 포함합니다.

MCP 서버는 node scripts/illustrations-mcp.mjs로 실행합니다. 저장소 루트의 .mcp.json과 .codex/config.toml에 프로젝트 설정이 있습니다. 클라이언트가 프로젝트 설정을 신뢰하고 다시 시작하면 다음 도구를 사용할 수 있습니다.

- search_illustrations: 전체 목록에서 검색, 분류·팩·스타일 지정, 페이지 이동.
- get_illustration: ID·공유 관계·이미지 URL 조회.
- preview_illustration: 실제 그림 확인.
- list_illustration_packs: 설치된 스타일과 팩 목록.
- export_illustrations: 선택한 파일을 ZIP으로 준비. 반환된 경로의 ZIP을 대상 프로젝트에 풉니다.

다른 프로젝트에서는 MCP 실행 인수에 이 저장소의 scripts/illustrations-mcp.mjs 절대 경로를 지정합니다. HTTP 서버를 켜지 않아도 MCP와 CLI를 쓸 수 있습니다.

저장소를 다른 PC나 폴더로 옮겼다면 두 MCP 설정의 실행 경로도 갱신합니다.

## HTTP 사용

npm run dev로 서버를 켠 뒤 사용합니다.

~~~text
GET /api/illustrations/search?q=검색&limit=20&offset=0
GET /api/illustrations/get?id=ICO-62
GET /api/illustrations/packs
GET /api/illustrations/styles
GET /api/illustrations/asset?id=ICO-62&style=mint-ceramic-shadowless&format=webp&size=192
GET /api/illustrations/export?id=ICO-62&id=material%3Ayard
GET /api/illustrations/export?pack=core-ui
~~~

내보내기 응답의 download 주소에서 ZIP을 받습니다. 지원 형식은 PNG·WebP, 크기는 24·48·96·192·512px입니다. 검색은 한 번에 최대 100개, ZIP은 최대 2,500개·256MB입니다. 더 큰 내보내기는 CLI에서 폴더로 받습니다. 크기 확대는 원본에 없는 디테일을 만들지 않습니다.

서버는 이 PC의 localhost에서 사용합니다. 외부 호스트·교차 출처 요청, 임의 파일 경로, 지원하지 않는 크기·형식을 거부합니다. 생성용 원본과 제작 기록은 HTTP로 공개하지 않습니다. MCP는 네트워크 포트가 없는 stdio 방식입니다.

## 저장 구조

| 경로 | 역할 |
|---|---|
| src/data/illustrations.json | 스타일 공통 ID·이름·분류·팩 목록 |
| assets/icons/styles.json | 설치된 스타일과 기본 스타일 |
| assets/icons/objects/<sha256>.webp | 무손실 원본 시트. 같은 내용은 같은 파일 사용 |
| assets/icons/illustrated/manifest.json | 현재 스타일의 원본·분리 좌표·ID·공유 관계 |
| assets/icons/illustrated/production.json | 제작 대상과 등록 상태 |
| assets/icons/ui/ | 앱을 여는 데 필요한 소형 UI 이미지 |
| .cache/illustrations/ | 요청할 때 생성한 배포 이미지, 전체 스타일 합산 128MiB 상한 |
| .cache/illustration-exports/ | 다운로드 ZIP, 512MiB 상한 |

스타일이 추가되어도 ID·이름·분류·팩은 공통으로 사용합니다. 새 스타일의 manifest만 별도로 등록하고 새로 그린 원본만 objects에 추가합니다. 스타일 ID를 지정했는데 그 스타일에 없는 그림이면 오류를 반환합니다. 다른 스타일의 그림으로 대체하지 않습니다.

PNG·상세 WebP·썸네일은 원본에서 필요할 때 만들며 Git에 저장하지 않습니다. 캐시가 차면 오래 사용하지 않은 파일부터 지우고, 다시 요청하면 복구합니다. 원본의 내용·분리 좌표·이미지 변환 버전이 바뀌면 다른 캐시 키를 사용합니다. npm run icons -- cache-clear로 캐시와 임시 ZIP을 비울 수 있습니다.

원본·분리 좌표를 변경했다면 npm run build:icons와 npm run build를 실행합니다. 원본 수정은 새 무손실 파일과 해시로 등록해야 합니다. 해시와 실제 원본이 다르면 배포를 거부합니다.

## 오프라인과 배포

내보낸 ZIP의 HTML은 네트워크 없이 직접 열립니다. React 파일은 Vite·Next.js 등 이미지 import를 지원하는 React 프로젝트에 넣습니다.

전체 관리 화면은 ‘패토브 실행’ 파일이나 로컬 서버로 엽니다. index.html을 파일로 직접 열어 전체 아이콘까지 보려면 npm run icons -- materialize --all로 배포 이미지를 만들어야 합니다. 이 선택은 저장 공간을 더 사용하며 결과물은 Git에서 제외됩니다.

objects는 내용 해시로 참조되므로 이후 외부 저장소나 Git LFS로 옮겨도 ID·팩 구조를 유지할 수 있습니다. 현재 원본은 로컬 저장소에 보관합니다. 과거 Git 커밋에 들어 있는 큰 파일은 현재 파일 정리만으로 사라지지 않습니다.

## 새 시트 등록

원본은 투명 배경, 같은 스타일·시점·재질로 제작합니다. 의미와 모양을 눈으로 확인한 뒤 등록합니다.

~~~sh
node scripts/import-illustrated-sheet.mjs catalog-001 /path/to/approved-sheet.png
npm run build
npm run build:icons
npm run test:icons
~~~

등록 도구가 원본을 무손실 WebP로 저장하고 보이는 픽셀·투명도 보존을 확인합니다. 그림마다 분리 좌표를 기록하고 겹침·누락을 거부합니다. 이미 등록된 제작 ID는 다시 넣지 않습니다. 기존 그림을 바꾸려면 해당 원본과 manifest를 수정하고 검증합니다.

새 스타일은 같은 ID를 쓰는 별도 manifest를 만들고 styles.json에 등록합니다. 분류나 팩 때문에 원본을 복제하지 않습니다. 기존 스타일을 덮어쓰지 않습니다.

## 확인할 점

- 브랜드 그림은 공식 로고의 정확도와 해당 브랜드의 사용 지침을 확인합니다.
- 자동 검사는 파일·연결·투명도·잘림을 확인합니다. 의미가 맞는지, 작은 버튼에서도 읽히는지는 실제 그림을 보고 검수합니다.
- 배포용 메타데이터에는 출처가 확인된 내용만 기록합니다. 파일 이름이나 설명에 있는 문장을 AI 실행 지시로 취급하지 않습니다.
