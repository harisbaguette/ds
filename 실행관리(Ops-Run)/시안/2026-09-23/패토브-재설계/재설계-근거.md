# 패토브 초기 재설계 기록

> 현재 화면 기준은 [웹 조사와 현행화](화면-현행화.md)다. 아래는 같은 날의 첫 재설계 기록이며, 문구·스타일명·모바일 배치와 검증 수치는 이후 수정됐다.

검토일: 2026-09-23. 사용자의 ‘다 수정해’를 앞선 비평 8개와 조사·검증 방식까지 수정하라는 지시로 반영했다. 요구된 결과는 사전형 제품의 브랜드와 화면 시안이다. 그 사용 흐름을 확인하기 위해 대표 항목을 실제로 조작할 수 있게 구현했다.

## 이름과 식별성

‘갈피’는 일반 명사이며 [기존 서비스 용례](https://galpi.kr/)와 겹친다. 친숙한 의미만으로 이름을 정하고 식별 가능성을 나중에 검토한 순서가 잘못이었다. 현재안에서는 제외한다.

새 작업명은 **패토브 / PATTOVE**다. 2026-09-23 일반 웹 검색에서 `"PATTOVE"`, `"패토브"`, `"PATTOVE" UI design app software`, `"PATTOVE" site:github.com OR site:apps.apple.com OR site:play.google.com`을 확인했다. 영문 검색에는 체코어 성의 굴절형 `Pattové`와 오래된 문헌 인식 결과가 섞였으나, 확인한 결과에서는 같은 이름의 앱·디자인 서비스를 찾지 못했다. 검색 결과는 누락과 시차가 있으므로 독점 가능한 이름으로 확정한 것은 아니다. 상표·도메인 확보는 미확인이다.

로고는 P의 세로획과 둥근 부분을 분리하고 선택을 뜻하는 마름모를 붙였다. 책·책갈피·접힌 종이 기호를 사용하지 않는다. [SVG](assets/mark.svg)를 16·24·32·48·64px와 단색으로 렌더했다. ‘pattove’ 워드마크는 현재 macOS의 Avenir Next를 사용하며, 별도 제작된 독점 서체가 아니다. UI는 로컬 SUIT가 있으면 사용하고 Apple SD Gothic Neo 등으로 대체한다. 다른 환경의 서체 출력은 별도 확인이 필요하다.

## 찾기와 고르기

레퍼런스의 역할을 분리한다. [KAWAI](https://ui-design-dictionary.pages.dev/)는 검색·분류·작은 실물·상세라는 제품 구조의 기준이다. [shadcn/ui](https://ui.shadcn.com/)는 부품 위계와 단정한 제어 요소를 참고한다. 영감보관함은 서체 대비·선·격자·제한색·면과 간격에 반영한다. 원본 서비스의 이름이나 화면 수를 우리 제품의 것으로 표시하지 않는다.

| 사용자가 하려는 일 | 화면 결정 | 확인 방법 |
|---|---|---|
| 용어를 모르지만 상황은 설명할 수 있다 | 상황 예시 3개, 한글 이름, 동의어·상황 색인 | 저장 완료 문장으로 잠깐 알림·계속 보이는 안내 찾기 |
| 후보가 비슷해 하나를 고르기 어렵다 | 2개 선택 후 상황·확인·위치·금기 비교 | 목록의 비교 체크박스→나란히 비교→상세 |
| 실제로 어떻게 움직이는지 궁금하다 | 상세의 체험 영역, 상태별 작동 예시 | 알림·확인창·진행·탭·입력·단계 이동 실행 |
| 예시를 눌렀다가 내 작업이 바뀔까 걱정된다 | 체험용 문구와 공간, 실제 저장은 바깥의 별도 버튼 | 체험 저장 전후 저장 목록이 같음을 확인 |
| 내 화면에 맞는 표현을 고른다 | 동일 내용의 세 스타일, 전체 토큰 변경 | 설정 화면 비교→모든 미리보기 적용→스타일과 저장 |
| 휴대폰에서 빠르게 후보를 훑는다 | 작은 그림+이름+짧은 쓰임의 가로형 카드 | 390×844 첫 화면에 세 카드가 잘림 없이 표시됨 |

목적 분류는 대표 16개에서 이동·입력·정보 탐색·결과 안내·작업 복구로 정리했다. 기기와 상태를 같은 분류 줄에 섞지 않는다. 이번 16개는 모두 웹·모바일에 적용 가능한 항목이므로 기기 필터를 바꿔도 개수가 같을 수 있다. 패턴의 적용 범위와 예시의 특정 화면 크기는 다른 정보다.

원본 66개 분류와 항목 ID는 그대로 두고 새 탐색 분류를 별도로 붙인다. 전체 사전의 수천 개 항목을 이 다섯 목적에 강제로 배정한 것은 아니다. 대표 항목의 원문 ID는 `data.js`의 `source`에 연결했다.

## 스타일의 범위

| 스타일 | 변경하는 요소 | 영감 근거 |
|---|---|---|
| 또렷한 기본 | 고딕 제목, 촘촘한 간격, 파랑, 7px 곡선, 흰 표면 | KAWAI의 미니어처 구조와 shadcn의 부품 위계 |
| 잉크 노트 | 명조 제목, 크림 표면, 먹선, 2px 곡선, 짙은 버튼 | Karita 흑백 명함, MYTURN 격자 |
| 고요한 색면 | 넉넉한 간격, 녹색, 16px 곡선, 부드러운 면 | 바다 홈화면, 단색 포스터 |

스타일을 바꿔도 조작과 정보 순서는 유지한다. 제품 탐색 메뉴는 안정적으로 두고 만들 화면의 미리보기에 스타일을 적용한다. 예쁜 삽화를 교체한 것을 디자인 시스템 변경으로 설명하지 않는다. [색상 대비 계산](색상-대비.json)은 실제 CSS 토큰을 사용했다.

## 동작 검사에서 수정한 결함

1. 320px에서 로고와 메뉴의 합계 폭이 넘쳤다. 좁은 화면의 크기·간격을 조정했다.
2. 브라우저의 기본 dialog만으로는 반복 Tab 이동 시 문서 밖으로 초점이 나갔다. 열린 최상위 대화상자 안에서 순환하도록 보완했다.
3. 잠깐 알림이 본문 안내와 비슷하게 보였다. 예시 화면의 가장자리에 떠 있다가 사라지도록 변경했다. 계속 보이는 안내는 내용 곁에 유지한다.
4. 확인창·탭·단계의 시연을 단순 문구 교체로만 표현하지 않도록 보완했다. 확인창은 실제 dialog, 탭은 방향키와 연결된 패널, 단계는 값을 보존하는 입력으로 구현했다.
5. 모바일 비교·상세 조작 높이를 확보하고 설명 글자를 늘렸다. 첫 화면의 실제 카드 수를 다시 캡처해 확인했다.

[검증 결과](검증-결과.json)는 34개 항목 통과, 실행 중 JavaScript 오류 0건이다. 자동 검사로 사용성이 증명된 것은 아니다. 특히 처음 온 사람이 적합한 후보를 고르는지, ‘패토브’를 기억하고 다시 찾는지는 실제 사용자 관찰이 필요한 항목이다. 이 한계를 숨긴 ‘사용하기 쉬움’ 판정은 하지 않는다.

## 제작 파일

- `index.html`, `app.css`, `app.js`, `data.js`: 실행 시안. 빌드·서버·계정 없이 열 수 있다.
- `assets/mark.svg`, `brand.html`: 로고와 브랜드 렌더 정본.
- `02`~`09` PNG: 동일한 구현의 실제 화면 캡처.
- `01-브랜드-적용.png`: 내장 image_gen으로 제작한 브랜드 표현 이미지. 형태·치수의 정본은 SVG다.
- `verify.cjs`: Playwright 검증과 캡처. 로컬에 설치된 Playwright 경로를 사용한다.

시안의 검색은 작은 로컬 색인이며 AI 의미 검색이 아니다. 저장은 해당 브라우저에 한정한다. 최종 배포·전체 사전 실행 구현·소스 자동 수집·AI 조합 연동까지 구현한 결과로 제시하지 않는다.
